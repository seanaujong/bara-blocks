# Explaining Software

> A small, stable set of document starters covers most writing about software: how
> a customer uses it, how a developer uses it, why a code change was made, and why a not-yet-built
> approach should be approved. Each decomposes into blocks — a problem statement, a step, a
> before/after pair, a decision — the same way an essay decomposes into a thesis and evidence.

## Starters

- **[Product Walkthrough](./starters/product-walkthrough/README.md)** — how a customer uses a
  product or feature, in their own terms.
- **[Developer Guide](./starters/developer-guide/README.md)** — how a developer uses a tool, API, or
  library.
- **[PR Description](./starters/pr-description/README.md)** — what a code change does, why, and how
  you know it works.
- **[Design Doc](./starters/design-doc/README.md)** — what should be built, which options were
  weighed, and why one was chosen.
- **[Architecture Overview](./starters/architecture-overview/README.md)** — the author's intended
  shape for a project, kept current: its layers, their contracts, and how to extend them.
- **[Module Contract](./starters/module-contract/README.md)** — a module's intended purpose,
  interface, and invariants, declared up front.
- **[Module Discovery](./starters/module-discovery/README.md)** — a module's usage reconstructed
  after the fact, when no contract was ever written.

## Blocks

**[blocks/](./blocks/README.md)** is the shared glossary — Problem Statement, Step,
Before/After, Code Snippet, Interface, Decision and Rationale, Summary — each described once here
rather than re-explained on every starter's page.
